How it works

Cheapest model first. Check. Step up if it fails.

That loop never changes. What changes is how much Horsy is allowed to do, and it earns each step on your own repo.

01 day one · zero risk

Verify

Every “done” gets checked before it is accepted. If the work isn’t there, you hear it now, not in code review.

02 changes nothing

Shadow

Horsy watches your sessions and tells you what it would have routed, and what that would have saved. Your models stay as they are.

03 per task type

Active

Turns on only for task types where your repo’s data shows it costs less and breaks nothing. Everything else stays on your default.

How verify works

Cheap checks first. A judge only where tests can’t tell.

1

Tests, lint, typecheck

Deterministic, local, free. Run first, every time there is something to run.

2

A judge, only where needed

When there are no tests to run, an independent model checks the work. Pluggable: you choose which.

3

Fail → one rung up

The task goes to the next model with the reason it failed, so it doesn’t repeat the same mistake.

FAQ

Questions devs actually ask.

Does it work on a Claude Max plan?

Yes. On a flat plan you don’t save money, you save quota: grunt work stops eating your Opus limits, so the plan lasts longer.

Will it slow me down?

Routing decisions run locally in tens of milliseconds. If Horsy fails or is slow, everything runs as before. It never blocks you.

What if it routes something wrong?

The check catches it and the task steps up one rung, with the reason. If a task type keeps losing, Horsy turns itself off for that type. You can also pin a model per task, or run /horsy off.

Does my code leave my machine?

Not to Horsy’s servers. Routing data is metadata only. If you use a remote judge for tasks without tests, it sees only the snippet it checks.

Does it beat just using Sonnet for everything?

We don’t know yet, and we won’t claim it until we’ve tested it on real coding sessions. The receipts will show it either way, including when the number is negative.

Does it touch my main session?

No. Opus keeps planning in your main session. Horsy only routes the subagents it delegates to.
